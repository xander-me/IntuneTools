# Project instructions

## Session handoff

Start with README.md and [STATUS.md](STATUS.md) for scope, current work, authorization, evidence and the next action. Follow existing project-specific instructions and the user's current authorization. Check actual Git branch/commit, uncommitted/untracked files, fetched remote, issues and PRs before resuming; an open PR or backlog item does not itself authorize implementation.

Keep one authoritative handoff: update STATUS.md's handoff at the end of each work session with completed work, remaining acceptance, tests and environment (including NOT RUN), useful findings, blockers/owner, next action and local/unpushed work. README/project design owns scope; STATUS.md owns current session state; issues own tasks. Link detailed decisions/evidence instead of copying them.

Preserve original notes and unfinished work. Use task branches and separate worktrees for simultaneous tasks; validate and commit/push within authorization, using PRs for substantial changes. Keep credentials and unnecessary personal/customer data out of Git. Follow the conversation language and existing documentation language. At completion record actual acceptance, limitations, owner and maintenance/recovery references; never infer deployment from tests or merges. User instructions take precedence.
